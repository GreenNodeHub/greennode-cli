    AgentBase CLI Command Rename — Design

    • Date: 2026-08-18
    • Repos affected: greennode-cli (code + docs), greennode-agentbase-integration-test
    • Status: Design — approved by user; proceeding to implementation plan
    • Review gate: This spec is local-only (docs/superpowers/ is git-ignored per CLAUDE.md). It is not committed.

    1. Goal

    Rename three AgentBase CLI command surfaces so the grn command tree matches the current GreenNode portal, and stop exposing internal AgentBase service/module names to end users in the public docs.

    # Current Target
    1 grn agentbase identity grn agentbase access
    2 grn agentbase catalog grn agentbase marketplace
    3 grn agentbase identity workload <verb> grn agentbase access agent-id <verb>

    Plus: drop the Backend service column from the AgentBase Commands Overview, and scrub internal agent-core-* service names and Go package paths from user-facing docs.

    2. Locked decisions

    1. Hard cut, no aliases. Old command names stop working immediately. No deprecated/hidden aliases. Rationale: agentbase is GA/early; the blast radius is the integration-test repo + docs, both of which we control.
    2. Keep the agent_identity profile key and cfg.AgentIdentity field. No profile migration; existing profiles keep their current agent. Accept a minor cosmetic mismatch (configure prints agent_identity while the command is access agent-id).
    3. Full internal-name scrub in docs. Drop the Backend-service column AND reword the agent-core-* service-name prose on the scattered pages AND remove Go package-path strings from the public docs/development/architecture.md.
    4. Top-level grn agentbase is NOT renamed. Only subcommands. API endpoints (/api/v1/agent-identities, /flavors, /openclaws) are NOT renamed.

    3. Noun policy in help text / output (LOCKED)

    The API resource is agent-identities; the portal field is agent-id (the CLI verb). Decision: keep the resource noun "agent identity" in help prose and runtime output; rename only the command path/verb.

    • Keep: "Current agent identity set to: %s", Short/Long prose that says "agent identity".
    • Rename: only Use strings and command-path references in help/examples.

    Rationale: faithfulness to the backend resource + minimal churn; the rename is the verb (workload -> agent-id), not the noun.

    4. Scope

    In scope

    • go/cmd/agentbase/ command Use strings + registration + help text that references the renamed paths.
    • go/cmd/agentbase/agentbase_test.go present/absent assertions.
    • Cross-references in go/cmd/configure/ (comments pointing at the renamed command).
    • docs/commands/agentbase/ — file renames, H1s, command-path lines, overview table.
    • mkdocs.yml nav (agentbase section).
    • Scattered agent-core-* prose + docs/development/architecture.md package paths.
    • CLAUDE.md stale fixes (bundled).
    • Integration-test repo: harness/matrix.go, fixtures/fixtures.go, *_test.go command strings + service filter keys.

    Out of scope

    • Top-level grn agentbase command name; the agentbase Go build tag.
    • Any API endpoint path or resource name.
    • agent_identity profile key / cfg.AgentIdentity field.
    • VKS, vserver, configure command names, README.md, CONTRIBUTING.md (no agentbase mentions).
    • report.sample.md / harness/report_test.go (only cover cr/gateway).

    5. Change inventory

    5.1 CLI code — go/cmd/agentbase/

    Command renames (cobra Use strings + AddCommand wiring unchanged in shape):

    File:line (current) Use now Use after
    identity.go:23 identity access
    identity.go:41 (group var workloadCmd) workload agent-id
    catalog.go:20 (catalogCmd) catalog marketplace
    catalog.go:39/45/51 children flavors/openclaw-versions/openclaw unchanged
    identity.go outbound-auth Use: "outbound-auth" unchanged unchanged

    Leaf verbs under workload (create/list/get/update/use/delete) and under outbound-auth (static/delegated/oauth2 + their leaves) are unchanged — only the group verbs move.

    Help/text references to update (command-path strings, not resource nouns): - agentbase.go:50-52 Long: 'grn agentbase identity workload use <name>' → 'grn agentbase access agent-id use <name>'. - catalog.go Long: "agent-core-runtime catalog" → "marketplace catalog" (also drops the internal service name — see §5.3). - configure/set.go:85, configure/list.go:66, configure/get.go comments: 'grn agentbase identity workload use|create --set-current' → 'grn agentbase access agent-id use|create --set-current'. - Implementation step: grep -rn 'agent-core-' go/ and fix any remaining user-facing help strings surfaced via --help/output.

    Tests: - agentbase_test.go:89 present-set {"workload","outbound-auth"} → {"agent-id","outbound-auth"}. - agentbase_test.go:110 leaf set {create,list,get,update,use,delete} unchanged. - agentbase_test.go:94-105 "gone" list (login/logout/whoami/config) — still valid; the message string referencing grn configure/grn login/grn logout unchanged.

    Unchanged: agent_identity profile key handling in configure/get.go, list.go, set.go (key stays agent_identity).

    5.2 Docs — docs/commands/agentbase/ + mkdocs.yml

    1. Overview table (docs/commands/agentbase/index.md, the ~lines 18–29 table): delete the Backend service column → keep Command group + Role. Relabel rows identity→access, catalog→marketplace. Reword the "6 backend services behind agentbase.api…" sentence to not name backends (e.g. "the AgentBase platform behind agentbase.api…").
    2. File renames to match new paths (git mv):
    3. docs/commands/agentbase/identity/ → access/.
    4. identity/workload-*.md → access/agent-id-*.md (6 pages).
    5. identity/outbound-auth-*.md → access/outbound-auth-*.md (prefix path inside each page identity outbound-auth → access outbound-auth).
    6. catalog/ → marketplace/ (10 pages).
    7. Keep context/, gateway/, runtime/, memory/, policy/, cr/, deploy/ directory names (unchanged).
    8. Page content: update every H1 + command-path line in renamed pages (grn agentbase identity workload … → grn agentbase access agent-id …; grn agentbase catalog … → grn agentbase marketplace …). Update deploy/index.md, deploy/up.md, deploy/status.md, deploy/destroy.md references to identity as a composed client → access.
    9. Second command-reference table (index.md ~lines 91–101): relabel identity/catalog rows + their link targets.
    10. mkdocs.yml nav (L75–209): rename section titles + file refs — Identity→Access, Catalog→Marketplace; update leaf file paths.

    5.3 Internal-name scrub in docs

    Pages that name agent-core-* services in prose → reword to concept-only: - catalog/index.md:3 ("served by the agent-core-runtime service"). - cr/index.md:3 ("agent-core-container-registry"). - policy/index.md:3,8 ("agent-core-policy"). - policy/decide.md:7 ("agent-core-gateway") — keep the "internal/advanced route" caveat, drop the service name. - gateway/index.md:3 ("agent-core-gateway"). - index.md overview prose (the "6 backend services" sentence + Backend-service table column — covered in 5.2.1).

    docs/development/architecture.md (public contributor guide — full scrub per decision 3): keep the conceptual description (self-contained agentbase stack, own auth/config/client) but remove Go package-path strings — internal/agentbase/auth/, internal/agentbase/config/, cmd/agentbase/, github.com/greennodehub/greennode-cli/internal/cli, cmd/<service>/, .github/CODEOWNERS paths. Replace with concept-level wording.

    5.4 CLAUDE.md (bundled stale fixes)

    • L22: identity.go # identity group (login/workload/outbound-auth) → access.go # access group (agent-id/outbound-auth) (file renamed, see §7.1).
    • L20–24 source tree: update the identity line → access.go # access group (agent-id/outbound-auth).
    • L130–132: delete the stale paragraph claiming agentbase is gated behind an opt-in build tag. Reality (L20, L149, register_agentbase.go): agentbase is GA, default-on, no build tag. Keep L130–132 consistent with the truth.
    • L74–82 internal/agentbase/ block: identity/ # identity API client + models → identity/ # access (agent identities) API client + models — internal Go package name internal/agentbase/identity is LEFT AS-IS (not user-facing; renaming it is pure import-path churn + merge-conflict risk). Only the CLAUDE.md comment label updates.

    5.5 Integration-test repo — greennode-agentbase-integration-test

    Service filter keys renamed to match command groups (decision: keep keys aligned with Cmd strings): - "identity" → "access", "catalog" → "marketplace" across harness/matrix.go (Op.Service + enum comment L10), *_test.go (RunService/ForService), matrix_test.go count map. - Cmd strings: identity workload … → access agent-id …; catalog … → marketplace … (matrix.go ~L77–108, L171–183). - fixtures/fixtures.go bare arg-slices: {"identity","workload",…} → {"access","agent-id",…}; {"identity","outbound-auth",…} → {"access","outbound-auth",…}; {"catalog",…} → {"marketplace",…} (L251, L255, L332, L335, L343, L346, L431). - catalog_test.go case "catalog openclaw …" → "marketplace openclaw …" (L36, L42, L52). - Generated reports (report.md, report-*.md) are git-ignored → regenerate, do not hand-edit. - Unchanged: runner.go:99/:322 (agentbase prefix) and the -tags agentbase build tag (L46/L48). Top-level command + Go build tag are not being renamed.

    6. Breaking change & sequencing

    • Breaking for any external script using grn agentbase identity … or grn agentbase catalog …. Add a "Breaking change" callout to the agentbase overview doc.
    • PR title uses Conventional Commits feat!: (squash-merged → release commit) so release-please triggers a major bump.
    • Two-repo coordination: the integration-test suite builds the CLI from ../greennode-cli/go. Land the CLI rename first (merged), then update the integration-test repo against the updated CLI. Coordinate branches so there is no window where the suite is red. (Both repos can be PR'd in parallel if the integration-test PR is merged after the CLI PR.)

    7. Locked sub-decisions

    1. Noun policy (§3): keep "agent identity" in help/output prose; rename only the command path/verb.
    2. Go source file identity.go → access.go: yes, git mv and update CLAUDE.md L22. Internal Go package internal/agentbase/identity: left as-is (not user-facing; renaming is pure churn + merge-conflict risk). Only the CLAUDE.md comment label updates.
    3. docs/development/architecture.md full scrub: confirmed — drop Go package paths (internal/agentbase/..., cmd/agentbase/, CODEOWNERS refs) from this public contributor guide, keep the conceptual description.

    8. Verification

    • go build ./... and go test ./cmd/agentbase/... ./cmd/configure/... green in greennode-cli/go.
    • grn agentbase --help shows access and marketplace (not identity/ catalog); grn agentbase access agent-id --help and grn agentbase marketplace openclaw --help resolve.
    • Old names error cleanly: grn agentbase identity … → unknown command.
    • Docs build (mkdocs serve) nav + pages resolve at new paths; no dead links; overview table has no Backend-service column.
    • grep -rn 'agent-core-' docs/ returns nothing user-facing.
    • Integration-test suite green against the renamed CLI.
